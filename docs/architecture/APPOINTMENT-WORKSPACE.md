# Immediate appointment form

PO rejected the embedded full modules in PR #239 as too slow and complex. The same Agenda large/fullscreen sheet now renders one compact form. Description/list-price input and price are visible immediately. Additional rows are optional. Incasso, Ricetta e documenti and Preventivo are native details sections: collapsing does not unmount fields. There is no tab navigation, PianoDrillDown, Piani page or IncassoModal in this form. Existing agenda actions remain explicitly available below the form, outside its primary flow.

One save button submits treatment, optional quote and optional payment; Salva e chiudi closes only after the existing DB adapter confirms them. buildTreatmentItem/buildNewPlan and planAssignmentForPatient remain domain authorities. Blank treatment/payment/quote is skipped, invalid or incomplete entered rows block all writes. One eligible plan is preselected; several require a choice; no plans shows the explicit New plan destination. Manual/list-price entry remains editable. Treatment is never automatically executed or paid; quotes retain the existing attivo lifecycle. No duplicated financial totals or formulas.

The existing DocMedico controller exposes a renderInline slot supplying its real fields, available document types, generation and archive logic. The compact sheet renders only direct field inputs and Genera PDF in its accordion, not the document module screen/header/type cards. Prescribing-vertical restrictions, PDF heading/patient data, existing archive and delivery actions remain. Ordinary document routes retain their original UI. PDF generation is explicit within the section, separate from treatment/payment save; clinical drafts keep DocMedico's existing persistence.

persistAppointmentEntry uses only the existing tenant-scoped DB adapter. It revalidates patient/appointment identity and reads plans before writing. New plans are awaited before the payment uses their actual server IDs. An explicit payment choice can target the new quote as an acconto using its confirmed ID. Existing-plan writes are reread and checked structurally, ignoring JSONB key ordering. All draft inputs are checked before the first write. Confirmed rows update App's plain state setters, avoiding duplicate optimistic inserts. Save taps are locked and header close disabled during pending persistence. This is sequential, not an atomic transaction; a failed/uncertain write stops the sequence and blocks automatic retry in the open form, showing confirmed-operation count. No compensating rollback or blind replay. Closing/reopening after an uncertain outcome requires checking the records; no server idempotency key or concurrent row-locking mechanism was introduced.

No schema, RLS, capability, tenant, financial formula or deployment changes. No production operations in verification. Existing immutable stable checkpoint preserved. Rollback: revert dedicated PR. Validation uses service tests with injected synthetic adapters and actual-component Chromium/WebKit flows at 375/768/1024/1440; no physical iPhone or real-account claim.

## Direct document retrieval
The compact Documenti del paziente section is at the top of the appointment form. Opening it loads medical metadata only from the existing patient archive. Recent items, search and quote/prescription filters stay inside the sheet; PDFs load only on request. Existing plan records are available as Preventivo / piano and use the canonical buildPreventivoPdf builder, preserving financial semantics. Records are patient-wide, not falsely attributed to this appointment. The list refreshes from App plan state after saves and reloads archive metadata after DocMedico confirms archival. Reopening the sheet retrieves the saved documents again. Existing archive opt-in settings remain authoritative; generation alone does not guarantee retention if archival is disabled or fails. No PDF data is copied to localStorage, no new schema/storage/public URLs. The existing in-app PdfViewerModal provides preview, download and native sharing and returns to the mounted form with its drafts unchanged.

## Dental visit form and per-tooth entry
The PO rejected the previous visual design and manual Duplicate button. The appointment surface now uses a single clinical card: description, unit price, tooth selector and a compact preview for each selected tooth. Secondary sections remain inline accordions; no module navigation. Odontogramma's optional touch layout has recognizable tooth outlines and accessible pressed states. Duplicate is removed. A multi-tooth selection remains one editable source row; each unique FDI tooth creates a separate canonical line at the entered unit price when explicitly saved. Unchecking removes only the draft-derived line; it never deletes saved records. Existing free-text sites stay one site. Per-tooth expansion applies only when requested by the dentistry form, preserving other callers.

Exact keyword impianto still prepares the PO-authorized price preset in integer cents: implant500, abutment150, crown remainder, minimum650. Dental site expansion runs first: two teeth produce six lines in a single canonical quote, no extra generic treatment. The displayed total is explicitly per tooth. Ordinary treatment rows and quote editor rows use the same site expansion. Existing lifecycle, explicit payment target precedence, no automatic execution/acceptance and uncertain-write handling remain unchanged.

Saved treatments are now visible inside the appointment, grouped with patient plan title/tooth/price. The section is patient-wide and labelled accordingly, without inventing appointment linkage. Confirmed saves return savedPlanIds; the section opens after a successful save and shows existing plans again when the appointment is reopened. A synthetic read-after-save test verifies both separate tooth rows survive a fresh adapter read; no real patient records were accessed or repaired.

DocMedico's existing favorites, exact-name medication completion, editable dose/posology/duration, explicit generation and archive policy remain unchanged.

## Larger booking editor
AgendaAppointmentForm.css scopes the appointment booking/editor to a full mobile viewport and a large desktop dialog. It supersedes legacy dock-clearance sizing specifically for this portaled editor, which sits above floating controls. Header and footer are fixed parts of the flex layout; only form content scrolls. Save/Cancel use Modal's existing footer slot. Other modal variants and agenda quick-action menus retain their styles. Browser tests verify viewport dimensions and actual close/save button hit targets, not just source CSS.
