# Personal document folders

PO request, 21 October 2026: all documents, rather than a special San Raffaele folder. Search should surface complete folders, allow whole-folder export/share, synthesis and document-based questions, and match Drive organization.

Uses existing `documenti.ente` folder identity and existing year/date fields as selectable year subfolders. No new database fields, policies, functions or migrations. `v_cartelle` and document lists paginate to an empty page, without an application-level folder limit. Deadline lookup is paginated in groups of 50 document IDs to avoid oversized URLs. Folder actions include all low-relevance records; recent/search pages remain explicitly partial result lists. Search chips open the complete folder, not just the matching records. Arbitrary user-defined subfolder names are not introduced.

Drive originals move (never copy or delete) to `Archivio personale/Cartelle/<ente>/<year>`. Missing ente uses `Senza cartella`; missing date uses `Senza data`. Encoded path identity is decoded when creating the actual folder name, preserving punctuation and avoiding sanitizer collisions. IDs and existing links remain stable. Existing clinical folder destinations remain unchanged. Existing scheduled `ordinaDrive_` handles past records; a per-document authenticated action allows the visible folder to be organized immediately, with success/error counts and actual Drive folder links. Photo import's existing scheduled exclusion is retained. No production move has been run in this development session.

ZIP export preserves original bytes and duplicate filenames. It includes a manifest of every requested record and any reason for omission. The UI labels partial exports explicitly. ZIP32 bounds are checked; app memory guard is 120 MB, individual original download uses the existing 15 MB preview byte limit. Larger files remain accessible through native Drive after organization; no claim of unlimited browser export. Web Share is invoked directly from a separate prepared-file tap and only shares an actual ZIP; no text-only fallback presented as file sharing. Recipient support for ZIP is outside the app: instructions explain extracting originals when required.

AI reads one original per authenticated request using the existing PDF/image/Office/text adapters and Claude/Gemini gateway. Existing clinical label AND clinical filename/sender heuristics are checked server-side before original access, including ZIP and manual Drive actions. The owner email/confirmed identity gate remains ahead of all new endpoints. No arbitrary Drive IDs/public URL access is added. The original-reading model reports readability and partial reads; existing 40k text/300-row spreadsheet conversion limits are shown as partial coverage. Provider truncation is an error. Reduction processes every successful source in groups of eight; source links and omitted/partial documents are available beside each answer. Question follow-ups reread the same document scope, not the global archive. Answers are ephemeral until page closure, not saved in `cartelle_ente.sintesi`. The old persisted metadata synthesis is explicitly labelled as catalog-only and capped at 80 documents. No training or new data retention.
