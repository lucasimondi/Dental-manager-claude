# Personal OAuth consent

The archive Auth server currently redirects to `https://personal.poliedrasoft.it/oauth/consent?authorization_id=...`. Previously the exact route fell through to Studio's index and App, causing a Studio login/agenda instead of consent. Personal uses the separate archivio-documenti Supabase project and the existing `poliedron-personal-auth` storage key. Passing its request to Studio's ConnectorAccess would use the wrong project.

The exact `/oauth/consent` and trailing-slash route now serve Personal HTML. Its entry mounts OAuthConsent instead of App, so no archive/agenda/document view mounts during consent. Login reuses Personal Accesso on the same URL, preserving the opaque authorization ID. Details, approval and denial go only through archivioDb.auth.oauth. Requested client, account and scopes are displayed, together with the broader user-rights API delegation. A fresh request requires an explicit click. Already-authorized redirects returned by Auth follow the documented OAuth flow.

Only a single opaque authorization_id is accepted. Query callback URLs are ignored; only HTTPS credential-free destinations returned by Auth are used. Load responses are ignored after effect cleanup; a ref prevents duplicate decisions. An uncertain decision removes the action buttons and requires restarting through ChatGPT, never automatic replay. No tokens or secrets are printed, stored in new locations, or sent to Studio. Auth remains the authority for clients, callback URLs, grants and user permissions; this change does not narrow the underlying Supabase delegated API rights.

Vercel no-store/no-referrer headers cover consent; the Studio service worker excludes the exact consent path from its SPA fallback, so it cannot replace consent with Studio. Studio `/connector/consent` remains unchanged. No schema, RLS, tenant, grants, financial semantics or deployment architecture changes. No direct production mutation or auth config edit.

Validation: Node tests cover rewrite precedence, exact route matching, malformed/duplicate authorization IDs and unsafe redirects. Full Node suite and both Vite builds run. Synthetic React fixture supports consent, deny, expired and uncertain scenarios without document/network operations. Cloud Browser cannot reach the container loopback dev server (connection refused), so browser validation is pending on the Vercel preview/released route. No live OAuth success or MCP tool test is claimed before release.

Release: dedicated PR, exact-head CI, explicit Product Owner merge approval under AGENTS.md; normal Vercel Git release. Smoke-test /oauth/consent without an ID (must show Personal error, never Studio), then restart the existing ChatGPT app connection with a fresh authorization ID. Test read-only tools and a synthetic new upload only; never modify existing records. Rollback is a PR revert to the prior application; leave stored archive data and grants intact. Golden checkpoint stable/2026-08-27-full-recovery is unchanged.
